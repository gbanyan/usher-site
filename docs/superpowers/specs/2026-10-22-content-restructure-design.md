## 1. 背景與動機

秘書長對目前網站內容架構不滿意，具體有三點：

1. 內容重複又分散，沒有滿足 NPO／罕病病友協會的需求。
2. 內容很久沒更新（全站最新文章停在 2026-02-02），已有的活動素材（YouTube 直播）沒有放上網站。
3. 過去規劃要做的事一直積壓。積壓清單以 `docs/site-content-review-2026.md`（2026-08-09 盤點）第 E、G 節為準，秘書長確認該盤點內容正確。

實際使用情境：病友與家屬聯絡協會時，最想知道的是「協會群組怎麼加入」、「可以問誰」。目前實際回答問題的人是**秘書長與理事長兩人**。LINE 群組是公開邀請連結，點了就能加入。

## 2. 目標、非目標、反目標

### 目標

- **導覽做減法**：以現有導覽為底稿，從 5 大項／11 子項減為 4 大項／10 子項（減法後 9 項，再加上本輪新增的常見問題，見 §4.1）。
- **新增常見問題頁**：只用網站既有內容回答，幫秘書長與理事長分擔群組裡重複回答的問題（見 §4.2）。這是本輪唯一處理的積壓項目。
- **補上 2026 會員大會活動紀錄**：新增一篇活動文章並嵌入直播影片（見 §4.3）。
- **清理 CMS 重複與錯誤**：合併重複分類、修正錯誤連結（見 §4.4）。

### 非目標（本輪不做）

- 首頁排版改版、照受眾或行動重新分類的導覽（方案 A、B 已被否決）。
- 其他積壓項目：捐款金流、志工頁、年度報告／財務公開、隱私政策、無障礙聲明、病友故事英文版、研究與開放科學頁。這些項目繼續留在 2026-08 盤點清單。
- 英文版 `/en` 的內容或導覽調整。
- 疾病介紹文章本身的醫學內容修訂（見 §6 的「交給協會」）。

### 反目標（做了就算失敗，即使技術上可行）

- **提高 LINE 群組的能見度**。秘書長明確表示維持現在的可見度（頁尾與聯繫頁），不要在首頁、導覽列或 FAQ 頂部放大群組入口。FAQ 裡可以提到群組，但只能作為回答的一部分，不能做成醒目的 CTA。
- **FAQ 出現未經確認的內容**。凡是需要秘書長或理事長確認的題目或句子（入會資格、會費、捐款、回覆者與回覆時間、建議掛哪一科、罕病名單資格），一律不上網站。不放「待補」、「即將推出」之類的佔位文字。
- **舊網址失效**。`/blog/*`、`/notice/*`、`/message` 等既有網址，以及被分享出去的連結，都必須仍然可用或正確轉址。
- 對醫療內容做出原文沒有的斷言。

## 3. 限制

- 遵守專案 `CLAUDE.md`：靜態優先、列表頁不可加 `searchParams`、Laravel API 在 8001 port、注意大小寫路徑、`categories?.length` 等選擇性鏈結。
- 內容來源是 Laravel CMS（`~/Project/usher/usher-manage-stack`）。後台已支援頁面（`/admin/pages`）與文章分類（`/admin/article-categories`）的新增、編輯、刪除。
- **CMS 正式環境的寫入由實作者直接執行**（秘書長 2026-10-22 授權，範圍限於本文件 §4 所列的操作）。執行路徑依 `usher-manage-stack/docs/DEPLOYMENT.md`：
  - 正式 CMS 執行在 `armub`（ssh alias），使用 Docker，資料庫是 SQLite，路徑為 `/home/gbanyan/docker/usher-manage-stack`。
  - 每批寫入前，先執行 `scripts/backup-armub-sqlite.sh <label>` 備份。
  - 透過 `docker compose exec app php artisan tinker`，用 Eloquent model 或既有 service 寫入，不直接寫 SQL。這樣既有的 observer、controller 才會觸發 `SiteRevalidationService` 的 revalidation webhook。如果某項操作在後台 controller 才會觸發 revalidation，要手動呼叫對應的 `revalidate*()`。
  - 寫入後用公開 API（`https://member.usher.org.tw/api/v1/...`）和正式網站核對結果。
  - 本專案範圍不需要修改 CMS 程式碼，也不需要重新部署 CMS。
- **網站部署**：`usher-site` 推送到 GitHub `main`，由 Vercel 部署（正式站回應帶有 `x-vercel-id` 標頭）。GitHub Actions 的 CI 只用 snapshot 模式做檢查。CMS 內容變更後要執行 `SNAPSHOT_API_URL=https://member.usher.org.tw/api/v1 npm run refresh:content`，並提交更新後的快照。
- 合併分類前，必須先把文章改掛到保留的分類，再刪除空分類，不能讓任何文章失去分類。
- 驗證：`npm run lint`、`npm run test`、`npm run build`、`npm run check:a11y`、`npm run check:content`、`npm run check:assets`。

## 附錄 A：FAQ 初稿（秘書長已核可方向）

> 本頁提供一般資訊，不能取代醫師診斷。每個人的類型與病程都不同，請與醫師或遺傳諮詢人員討論。

**認識尤塞氏症**

**Q. 什麼是尤塞氏症？**
尤塞氏症是一種罕見的遺傳性疾病，主要特徵是先天性的聽力損失，加上視網膜色素病變造成的視力退化，例如夜盲、視野漸漸變窄（隧道視野）。有些類型還會有平衡問題。→〈什麼是尤塞氏症？〉

**Q. 有哪幾種類型？要怎麼知道自己是哪一型？**
傳統上依症狀分成第一、二、三型，近年也有研究提出第四型。目前比較準確的方式是做基因檢測，找出是哪一個基因造成的。知道類型和基因，有助於了解病程、規劃生活，也能追蹤相關的臨床試驗。→〈什麼是尤塞氏症？〉

**Q. 會遺傳嗎？其他家人需要檢查嗎？**
尤塞氏症是體染色體隱性遺傳。父母通常是沒有症狀的帶因者；如果父母雙方都帶有變異基因，每一胎有四分之一的機會罹病。家人要不要檢查，建議先接受遺傳諮詢。→〈眼科醫師觀點〉、〈視聽障礙疾病之遺傳學〉

**Q. 會做哪些檢查？**
常見的檢查有聽力測試、視力、視野、眼底照相、視網膜電位圖、視網膜斷層掃描，以及基因檢測。→〈眼科醫師觀點〉

**Q. 現在有治療方法嗎？**
目前還沒有能根治的方法，主要是管理聽力、視力和平衡對生活與學習帶來的影響；只要輔助得當，在生活學習上都可以相當獨立。國外有多項臨床試驗正在進行，可以到 ClinicalTrials.gov 查詢。服用任何補充劑（例如維他命 A）之前，請先和醫師討論。→〈眼科醫師觀點〉

**生活與福利**

**Q. 可以申請哪些證明或補助？**
常見的有身心障礙證明、重大傷病卡、輔具費用補助、身心障礙基本保證年金。→〈社會福利資源〉

**Q. 智慧眼鏡、點字觸摸顯示器可以申請補助嗎？**
點字觸摸顯示器目前在補助項目內；智慧眼鏡還沒有。協會已經向衛福部提出倡議，希望把智慧眼鏡納入補助，並提高點字顯示器的補助上限。→〈【倡議】將智慧眼鏡與點字觸摸顯示器納入更可近用的輔具補助〉

**關於協會**

**Q. 有問題可以問誰？**
可以加入協會的 LINE 社群（見〈聯繫資訊〉）和其他病友、家屬交流，或寫信到 president@usher.org.tw。

**Q. 協會平常有哪些活動？**
協會會舉辦講座、會員大會、藝術共創等活動，也參與政策倡議。活動紀錄與直播影片都整理在「最新消息」的「活動與公告」。
